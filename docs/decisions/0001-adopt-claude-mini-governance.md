# 0001. Adopt claude-mini enterprise workflow

## Context and Problem Statement

The `digest` project has existed since 2025 as a personal news digest generator and has reached v2.0.0 (a rewrite into the radar + irritator + delivery pipeline, completed on 2026-04-09). The pipeline has been stopped since 19 April 2026: the last successful `discover:` commit is dated 2026-04-19, with no `digest:` pushes or manual interventions since. The cause of the failure has not been diagnosed at the time of this ADR's adoption.

In parallel, bootstrapping of the `claude-mini` project on a Mac mini 2018 is complete (see claude-mini ADR-0001..0011): an enterprise workflow with governance hooks, two-voice review and ADR-gated planning. This workflow has already been exercised in a smoke test and on `claude-mini` itself.

Further work on `digest` requires a choice: continue ad-hoc development directly on `main` (as before), or adopt the same workflow as `claude-mini`.

## Decision Drivers

* The digest history on main mixes development feat/fix commits with autogenerated `digest:`/`discover:` pushes from GitHub Actions. Diagnosing regressions (such as the 19 April failure) is difficult; the git log is inseparable from the data log.
* v2.0.0 is a live product, but it is currently broken; this is the only window for architectural rework without risking production.
* The investment in `claude-mini` should pay off across several projects; otherwise, the pipeline is overhead for a single repository.
* Without ADRs in digest, there is no way to formally record future decisions (particularly the upcoming split into code and runtime repositories).

## Considered Options

* **Option A: Fully reset main, with a clean history and bootstrap from scratch.** Maximizes cleanliness, but destroys product development history and tags, and breaks any external SHA links. Considered and rejected during the session.
* **Option B: Install governance on the current main through the `chore: bootstrap` carve-out, preserving history.** All new work goes through a feature branch + PR; the old history remains on record. ADR-0002 will later address the architectural restructuring (code/runtime split).
* **Option C: Do not install governance; continue ad-hoc development.** Preserves iteration speed, but does not resolve the mixing problem or provide a place for a formal split decision.

## Decision Outcome

Chosen option: **Option B** — install governance on the current main.

Reasons: (1) digest is complex enough to justify the pipeline: v2.0.0 already encounters regressions that are hard to diagnose without a structured process; (2) resetting main (A) erases evidence without fixing the architecture: mixing development and runtime is a repository-topology problem, requiring a separate ADR rather than a retouched history; (3) without governance (C), there is no place to formally discuss the upcoming split, and `/plan` and `/advisor` cannot be invoked.

### Positive Consequences

* The upcoming split into `digest` (code) and `digest-runtime` (data) will receive formal consideration through ADR-0002.
* The 19 April failure will be recorded as an issue and become input to ADR-0002, rather than being addressed with a hotfix.
* All subsequent feat/fix commits go through PRs, separating the development git log from future data commits.
* User-scope claude-mini (`~/.claude/`) is used by a second project, validating the pipeline's suitability for multiple projects.

### Negative Consequences

* The digest/discover commit history in main remains mixed with development; readability improves only going forward, not retrospectively.
* Rule 4 (no feat commits on main) potentially conflicts with autogenerated `digest:`/`discover:` pushes from Actions. The workflow is not working at the time of this ADR, so the conflict does not materialize. If the split (ADR-0002) moves these pushes to a separate repository, the conflict disappears. If ADR-0002 does not happen or decides otherwise, a carve-out in `pre-commit-governance.sh` or a bot-author-based allowlist will be needed.
* `claude-mini` becomes a dependency: changes to its workflow may require resynchronizing digest. This is the cost of a reusable pipeline.

## Out of scope for this ADR

* Diagnosing the 19 April failure — a separate issue, input to ADR-0002.
* Architectural code/runtime split — ADR-0002.

## Confirmation

* `~/code/claude-mini/bootstrap/universal-setup.sh --check` from `digest` returns no drift.
* `~/bin/mini-health` in `digest` reports the presence of the commit-msg hook.
* An attempt to run `git commit -m "feat: ..."` directly on main after this PR is merged is blocked by rule 4.
* The first ADR-gated workflow — issue + `/plan` + `/advisor` + ADR-0002 on the split — completes end-to-end.

## Re-visit Trigger

* `claude-mini` substantially changes its workflow (for example, abandoning two-voice review), requiring an assessment of whether governance remains appropriate for digest.
* `digest` ceases to be an active product, making governance overhead without a return.
* A major Claude Code update breaks compatibility with installed hooks/agents.
